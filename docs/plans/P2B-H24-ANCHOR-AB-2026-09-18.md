## 1. The question, restated empirically

The h-24 daily anchor (`daily_loop_producer.py` → `daily_loop_output.json` →
`intraday_bridge.py` → `anchor_h24.json`) is a **dangling writer** — the live product
(`intraday_runner.py`) reads NEITHER artifact, and the intended consumer
(`core/intraday/backtest.py::HourlyBacktest`) exists only as an orphaned `.pyc`.

The architectural question ("restore the consumer vs. cut the bridge") was argued in
`DAILY-LOOP-PRODUCER-DISPOSITION-2026-09-18.md`, which landed on **RESTORE** by
reasoning alone ("a missing consumer means restore the consumer, not delete the
producer"). Dan rejected reasoning-as-answer: **build both, measure, then decide.**

This doc resolves it with numbers.

## 2. What the anchor actually is (from the orphaned `.pyc` + bridge source)

Disassembly of `backtest.cpython-311.pyc` recovered the original scorer's probability
model (`HourlyBacktest._estimate_hourly_probability`):

```
base        = 0.55 if actual_dir == 'up' else 0.45   # direction prior
hour_factor = (24 - hour_before) / 24.0
modulated   = base * (0.7 + 0.3 * hour_factor)
noise       = np.random.normal(0, 0.02 * hour_before / 24.0)
prob        = clip(modulated + noise, 0.1, 0.9)
```

Two facts stand out:

1. **The original scorer never read `anchor_h24.json`.** Its "prior" was a hardcoded
   `0.55/0.45` split on `actual_dir` — the *ground-truth label itself*. That is **oracle
   leakage** (it peeked at the answer), not a daily-LOOP prior.
2. **The intended Bayesian seam is real and documented** in
   `core/intraday/recalibration_loop.py::update_belief`:

```
updated_prob = (prior_belief*prior_weight + new_prob*new_weight)
             / (prior_weight + new_weight)
```

The anchor is the `prior_belief`; the intraday signal is `new_prob`. So the A/B isolates
whether seeding `prior_belief` from the daily-LOOP anchor adds calibrated directional
edge over a flat prior.

## 3. Measurement setup

- **Truth set:** the ultimate suite's correct-axis labels — **1,537 labels** (43 dates,
  2026-08-06 → 2026-09-18), strike-crossing direction vs date-tiered settlement temp
  (`core/settlement_outcome.strike_crossing_direction`), NOT day-over-day. Truth is
  **82.2% up-skewed** (1,264 up / 273 down).
- **Anchor artifact:** `data/intraday/anchor_h24.json` — a *single cross-section*
  (daily date 2026-09-17), 20 stations, per-station `probability` (which IS P(UP):
  DOWN stations carry 0.05–0.30, UP stations 0.70–0.95) and `confidence` 0.50–0.98.
- **Arms (all on the same 1,537 labels):**
  - **A (WITH anchor):** prior = anchor per-station P(UP) + confidence weight; then a
    signal-neutral intraday update (`new_prob=0.5`, fixed weight) so the prior dominates
    and the delta vs. B isolates the anchor's marginal pull. Reported as both
    prior-only and prior+update (identical results — the update is signal-neutral).
  - **B_flat (WITHOUT anchor):** flat prior 0.5, zero weight → no directional claim.
  - **B_empirical (reference):** always-UP at the 82% base rate — the honest "no-skill
    long-bias" baseline every directional model must beat.
- **Metrics:** directional accuracy, **MCC** (imbalance-immune — the honest skill
  metric), **ECE** (calibrated confidence, 10 bins), **Sharpe** (annualized, unit bets,
  sqrt(252)). Definitions identical to `ultimate_suite.py`.

**Axis flags:** every number below is on the **strike-crossing axis** (settlement temp
vs strike), NOT day-over-day. Truth source = `reconstruct` (T-contract strikes parsed
from `kalshi_market_snapshots.db` joined to `settlement_truth` date-tiered temps).

## 4. Results (side-by-side)

| Metric | **A — WITH anchor** | B_flat (WITHOUT) | B_empirical (always-UP) |
|---|---|---|---|
| n | 1,537 | 1,537 | 1,537 |
| Directional accuracy | **56.9%** | 17.8% | **82.2%** |
| **MCC (skill)** | **−0.086** | 0.000 | 0.000 |
| TP / FP / TN / FN | 804 / 203 / 70 / 460 | 0 / 0 / 273 / 1264 | 1264 / 273 / 0 / 0 |
| **ECE (calibration)** | **0.348** | 0.322 | 0.077 |
| **Sharpe (annualized)** | **−2.05** | −13.39 | +13.39 |

## 5. Interpretation

**The anchor carries net-negative skill.** Three independent signals agree:

1. **MCC = −0.086 (negative).** The anchor's directional calls are *anti-correlated*
   with truth — it is not merely uninformative, it is *actively wrong*.
2. **Accuracy 56.9% < 82.2% base rate.** The anchor underperforms the dumb
   always-UP baseline by 25 points. Its station-level DOWN calls are systematically
   wrong against an up-skewed truth set.
3. **Sharpe −2.05 < 0.** The anchor's high-conviction (confidence 0.7–0.98) wrong calls
   turn its net P&L negative, while always-UP returns +13.39.

**Root cause (empirical, not speculative):** the anchor is a *single cross-section*
(one day's intraday signal snapshot) used as a *station-level static prior* across 43
dates. It assumes station-level stationarity that the data does not support. Per-station
truth up-rates are 0.56–0.96 — *every* station is majority-UP — yet the anchor emits
DOWN for 7 stations (KBOS, KDCA, KLAS, KMDW, KMSP, KNYC, KPHL) that are actually
73–96% UP. The anchor even misfires on its own date (e.g. KPHX anchor=UP but 2026-09-17
truth=DOWN; KBOS anchor=DOWN but truth=UP).

**Why the disposition doc's RESTORE reasoning fails:** RESTORE argued "a missing
consumer means restore the consumer." The A/B shows the consumer would be *consuming a
wrong-sign prior*. Restoring the consumer without first fixing the prior's sign would
wire a *loss* into the intraday scorer.

## 6. Conclusion

**Arm B (WITHOUT anchor) wins — but not by being good; by being honest.**

- The anchor (Arm A) has **negative MCC and negative Sharpe** on the correct-axis truth
  set. It is worse than random and worse than no-skill long-bias.
- Arm B (flat prior / no anchor) has **zero skill (MCC 0.0)** — it makes no claim, which
  is the correct baseline given the anchor's available form (a single non-stationary
  cross-section).
- Neither arm demonstrates exploitable directional edge *from the anchor*; the only
  positive Sharpe (+13.39) comes from the structural up-skew, which is a market
  observation (Kalshi HIGH strikes set below realized temps), not a signal.

**Recommendation:** Do **not** wire the h-24 anchor into the intraday scorer as-is.
The anchor, in its current single-cross-section form, is a **negative-edge prior**.
Concrete next step — one of:
1. **Cut the seam** (Arm B end-state): deprecate `daily_loop_producer.py` +
   `intraday_bridge.py` as dangling writers, and formally record the h-24 anchor as
   deprecated. This matches the measured result.
2. **Rebuild the anchor as a per-date prior** (not a static station lean) and re-run this
   exact A/B before any wiring — the current artifact cannot support a per-date prior
   because only one day was ever produced.

Dan holds the wire-in decision. This doc is build-and-test evidence, not a wiring change.
